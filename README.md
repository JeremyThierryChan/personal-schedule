# Personal Schedule · 个人时间表

一个极简的静态「个人时间表」网站：**打开网页立刻就能看到忙碌 / 空闲时间**；在页面里输入姓名并验证通过后，才会显示**具体日程**。

- 技术栈：Astro + TypeScript + Tailwind CSS，纯静态，无后端 / 无数据库 / 无登录
- 部署：GitHub Pages（push 到 `main` 后由 GitHub Actions 自动构建部署）
- 平时只需要改这五个文件：`src/data/schedule.json`、`src/data/visitors.json`、`src/data/contact.json`、`src/data/settings.json`、`src/data/services.json`

### 页面结构（从上到下）

| 区块 | 内容 |
| --- | --- |
| **顶部 toolbar（吸顶）** | 第一行：标题 + **日/周/月切换** + **🔒 输入姓名** + **📅 预约我的时间**<br>第二行：今天是… · 访客状态 · **⏰ 最近可约**（最近 3 个够长的空闲时段） |
| **时间表** | 三色图例 + 日期导航（← / 日期 / → / 回到今天）+ 时间轴网格 |
| **📚 我能教什么** | 科目和形式说明（来自 `services.json`） |

设计说明：

- **所有控件和关键信息都收进吸顶 header**：时间轴有 940–1100px 高，滚下去的时候 日/周/月、预约按钮、最近可约都不会跟着消失。
- **预约是浮层**：按钮在 header 里，面板浮在按钮下方，**点面板外面或按 Esc 自动收起**。
- **最近可约排成一行**：`今天 12:05–18:00（5小时55分钟） · 明天 08:00–18:00（10小时）`；
  **手机上只保留最近的一条**，免得 header 太高。
- **手机上的按钮和提示会缩短**：「🔒 姓名」「📅 预约」「访客视图」，避免 header 换行太多。

### 页面使用方式

1. 打开网站 → 顶部先看到「最近可约」，再往下是**默认周视图**，直接看到时间表（只有「忙碌 / 空闲」，不需要输入任何东西）。手机上一屏显示 3 天，左右滑动看其余日期。
2. 想看到具体活动名称 → 点右上角的 **🔒 输入姓名** → 填名字 → 点「查看详细日程」。
3. 验证成功的姓名会记在浏览器本地（`localStorage`），下次打开直接显示具体日程；点 **退出** 可以回到访客视图。
4. 想约时间 → 顶部「最近可约」卡片里点 **📅 预约我的时间**，展开就是电话、微信和时段价格。

### 三种视图

顶部 **日 / 周 / 月** 切换（**默认周**），都用同一个「锚点日期」，前后箭头按视图自动换步长（±1 天 / ±1 周 / ±1 月）：

| 视图 | 布局 | 每个方块写什么 | 前后箭头 |
| --- | --- | --- | --- |
| **日** | 时间轴网格（1 列）：纵轴是钟点，日程是**方块** | **具体事项**：活动名 + 时间段 + 类型/地点 + `details` 全文 | ±1 天 |
| **周**（默认） | 时间轴网格（7 列，周一 → 周日，共一条时间轴）；手机上每屏 3 天可左右滑 | **只写摘要**：活动名 + `类型 · 地点` | ±1 周 |

### 方块长什么样

```
┌──────────────────────┐
│ 18:00                │ ← 开始时间贴在方块顶边（顶边就是这节课的开始时刻）
│ 全慧文苑 晚托         │ ← 标题：自动换行，放不下才省略号
│ 18:00–21:00 的正文…    │
│ 21:00                │ ← 结束时间贴在方块底边
└──────────────────────┘
```

方块高度是固定的（由时长决定），所以文字必须自己让位。优先级从高到低：

1. **上下两个时间永远完整** —— 两行都是 `shrink-0`，空间不够时只挤标题。
2. **标题自动换行**，实在放不下才用省略号。行数不是写死的：渲染完按方块的**真实像素高度**
   算一次（`applyTitleClamps()`），窗口缩放 / 横竖屏切换会重算。
3. **摘要（类型 · 地点）和具体事项**是次要信息，放不下就整行收起来；
   方块太矮时连标题也收起来，**只留上下两行时间**。

### 过去的时间会变灰

已经过去的时间（按北京时间）盖一层 `bg-slate-500/10` 的浅灰，避免把过去和将来搞混：

| 哪一天 | 遮罩 |
| --- | --- |
| 今天 | 从 `00:00` 到现在（每分钟跟着长） |
| 过去的日子 | 整列变灰 |
| 将来的日子 | 不画 |

`空闲 / 休息` 方块同理：标签换行，里面的时间段不会被截断。
| **月** | 日历格子 | **只显示这一天的空闲时长**（例如 `空闲 9.5 小时`），不列具体日程 | ±1 月 |


### 日历网格怎么读

- **纵向位置 = 开始时间，方块高度 = 持续时长。**
  时间轴总跨度 1439 分钟（00:00–23:59），所以 `09:00–10:30` 的方块在 **37.5% 处、高 6.3%**，`18:00–21:00` 在 **75.1% 处、高 12.5%**。
- **颜色（三种）**：玫红 = **忙碌**（有安排）· 靛蓝 = **休息**（个人时间，默认 22:00–次日 08:00）· 浅绿 = **空闲**（真正能约的时间）。左上角有图例。
- **时长统一写成「X小时Y分钟」**，例如 `空闲 1小时30分钟`、`休息 8小时`、`45分钟`（整点时不写多余的「0分钟」）。够高的方块还会附上时间段；方块本身的高度也直接反映有多久。
- 日视图上方有一行汇总：`忙碌 3小时（1 段） · 休息 10小时 · 可约 11小时`。没安排的那天写「今天没有安排 · 休息 10小时 · 可约 14小时」。
- **时间重叠**的日程会自动**横向并排**分成两列，不会互相盖住。
- 今天那一列会有底色，并画一条跟着当前时间走的**「现在」红线**（每分钟自动更新）。
- 方块里的字按高度自动取舍：够高才显示第二行、第三行；鼠标悬停（tooltip）永远给出全部信息。
- **点周视图的某一列、或月视图的某一格，会跳到那天的日视图。**

### 滚动方式

- **纵向**：时间轴是**完整的一天 00:00–23:59**（内部按 24:00 计算，这样时长都是整的；界面上把 24:00 显示成 23:59），
  高度固定（手机 940px / 桌面 1100px，对应每小时约 39 / 46px），**卡片内部不会纵向滚动**，要看别的时间就滚整个页面。
- **横向**：只在**手机上周视图**可以左右滑（一屏正好 3 天）；**桌面完全不滚动**，7 列按宽度平分铺满，没有任何滑块。
- 左边的时间刻度**固定在左侧**（不在滚动容器里），左右滑日期时时间参照不会跟着跑掉。

### 电脑 / 手机

| | 电脑（≥1024px） | 手机 |
| --- | --- | --- |
| 周视图 | 7 列全部铺满窗口，不滚动 | **一屏 3 天，左右滑动**看其余日期 |
| 日视图 | 1 列铺满 | 1 列铺满 |
| 每列宽度 | 随窗口拉宽 | ≈ 屏幕 1/3，能显示活动名 |
| 时间刻度 | 每小时一个（00:00–23:00 + 23:59） | 每 2 小时一个（免得挤） |
| 月视图格子 | 显示 `空闲 9.5 小时` | 紧凑写 `9.5h` |

### 时间都是北京时间

日程数据来自 Apple 日历（`TZID=Asia/Shanghai`），所以：

- 页面上的**「今天」和「现在」红线都按北京时间计算**，不跟随访客电脑的时区 —— 国外访客打开也不会把红线画错位置或算错日期。
- 标题下面会标一行「**· 北京时间**」，避免误会。
- 固定按 UTC+8 处理（中国 1991 年后没有夏令时），不依赖任何时区库。

### 访客 vs 授权

- **访客**：看得到所有方块的位置、大小和时间段，但方块上只写「忙碌」，看不到活动名称。
- **授权访客**：方块上直接写活动名称。

## 2. 修改日程：`src/data/schedule.json`

有两种改法：**手写 JSON**，或者**从 Apple 日历自动导入**（见 2.2）。

### 2.1 手写：`src/data/schedule.json`

**只写「忙碌」的时段**，空闲时间会自动算出来。

```json
[
  {
    "date": "2026-09-28",
    "start": "09:00",
    "end": "10:30",
    "title": "数学辅导",
    "type": "学习",
    "location": "线上 Zoom",
    "details": "讲解第 5 章定积分，带上上次的习题册"
  }
]
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `date` | ✅ | `YYYY-MM-DD` |
| `start` / `end` | ✅ | `HH:MM`，24 小时制 |
| `title` | ✅ | 活动名称，**只有授权访客能看到**；访客只会看到「忙碌」 |
| `type` | | 事务类型（`学习` / `会议` / `运动`…），**周视图的摘要**会显示 |
| `location` | | 地址 / 地点，**周视图的摘要**会显示（和 `type` 拼成 `学习 · 线上 Zoom`） |
| `details` | | 具体做什么，**只在日视图里显示**（周视图、月视图都不显示） |

三个视图显示的详细程度不一样：

| | 日 | 周 | 月 |
| --- | --- | --- | --- |
| `title` | ✅ | ✅ | 不显示 |
| `type` / `location` | ✅ | ✅（摘要） | 不显示 |
| `details` | ✅ | 不显示 | 不显示 |
| 空闲时长 | ✅ | ✅ | ✅（唯一内容） |

`type` / `location` / `details` 都是可选的，不写就只是少显示一行，不会报错。

空闲时间自动计算示例（一天默认 `08:00–23:00`）：

```
写入：09:00-10:30 数学辅导、14:00-16:00 项目工作
自动生成：
  08:00-09:00  空闲
  09:00-10:30  数学辅导      （访客看到「忙碌」）
  10:30-14:00  空闲
  14:00-16:00  项目工作      （访客看到「忙碌」）
  16:00-23:00  空闲
```

注意：

- 一天没有写任何日程时，页面显示「今天没有安排 · 全天空闲 24 小时」。
- **时间轴是完整的一天：`00:00 – 23:59`**（底部会补一个 `23:59` 的收尾刻度），所以凌晨或深夜的安排也不会被裁掉。
  `00:00–23:59` 是 `computeRange()` 的默认值；万一数据真有超出这个范围的安排，它还会自动扩到整点兜底。
- 两个时段首尾相接（`12:00-14:00` + `14:00-16:00`）会显示成两行；真正重叠的时段会自动合并。

### 2.2 从 Apple 日历导入：`日历/*.ics`

把 Apple 日历导出的 `.ics` 放进项目根目录的 **`日历/`** 文件夹，然后：

```bash
npm run import-ics      # 读 日历/*.ics → 重写 src/data/schedule.json
```

脚本会打印报告（读了几条、展开成几条、覆盖哪些日期、有哪些警告）。

**`日历/` 已经写进 `.gitignore`，永远不会被 push**；要提交的是它生成出来的
`src/data/schedule.json`（GitHub Actions 靠这个文件构建）。所以流程是：

```bash
# 1. 从 Apple 日历重新导出 .ics，覆盖 日历/辅导班.ics
npm run import-ics          # 2. 重新生成 src/data/schedule.json
git add .
git commit -m "update schedule"
git push                    # 3. 只有 JSON 会被推上去
```

> ⚠️ **导出时一定要用同一个文件名覆盖**（`日历/辅导班.ics`）。
> 如果导出成了 `辅导班 2.ics` 之类的新名字，「日历」文件夹里就会同时存在**两个日历文件**，
> 于是导入脚本会认为你是"多日历"，给**全部条目**都加上 `type` 字段 —— 一次改动 300+ 行，
> 虽然功能没问题，但 diff 会很难看。多出来的文件记得删掉。

导入脚本做了什么：

| 处理 | 说明 |
| --- | --- |
| 重复日程 `RRULE` | 展开成一条条具体日期。支持 `FREQ=DAILY` / `FREQ=WEEKLY`，以及 `INTERVAL`、`COUNT`、`UNTIL`、`BYDAY` |
| 排除日期 `EXDATE` | 被排除的那几次不会生成（同一条 `EXDATE` 可以有多行） |
| 无限重复 | 没有 `UNTIL`/`COUNT` 的事件最多展开 **365 天 / 400 次**，并在报告里提醒 |
| 不支持的规则 | `MONTHLY` / `YEARLY` 只保留第一次，并在报告里提醒 |
| 时区 | 固定按 `Asia/Shanghai (+08:00)` 处理（`.ics` 里的 `Z` 时间会自动换算） |
| `LOCATION` / `DESCRIPTION` | 有的话会写成 `location` / `details` 字段 |
| `type` | 只有当「日历」文件夹里有**多个** `.ics` 时才写（用日历名当类型，单个日历时避免每条都重复） |

零依赖，就是一个 `node scripts/import-ics.mjs`，不用装任何东西。

#### 本地开着 `npm run dev` 时是全自动的

启动开发服务器后，终端会打印：

```
[watch-calendar-folder] 正在监听「日历」文件夹，.ics 有变化会自动重新导入
```

之后只要你往 `日历/` 里**加新 .ics / 覆盖旧的 / 删掉**，它就会自动：

1. 重新跑一遍导入（日志直接打在你的终端里）
2. 若日程真的有变化 → 浏览器**自动刷新**，页面立刻是新数据

几个细节：

- 只在 **`npm run dev`** 时生效（用的是 Astro 的 dev 专属钩子），**不影响 GitHub Actions 构建**。
- 靠「文件名 + 大小 + 修改时间」的指纹判断，一次保存触发多个文件系统事件也只会导入一次。
- **不会在启动 dev 时自动导入** —— 所以如果你手改过 `schedule.json`，不会被覆盖；只有 `.ics` 真的变化了才会重写它。
- 改完记得 `git add src/data/schedule.json` 提交，否则线上不会更新。

> ⚠️ **重要**：`日历/` 不进 git 只是不让**原始 `.ics`** 进仓库；导入后的日程数据**会**写进
> `schedule.json` 并嵌入网页，所以**线上页面的源码里仍然能看到全部日程**（见第 5 节）。

## 2.9 个人休息时间：`src/data/settings.json`

每天的固定休息时段，用**靛蓝色**方块占掉，而且**不算空闲时间**（也就是说访客看不到这些时段可约）：

```json
{
  "restStart": "22:00",
  "restEnd": "08:00"
}
```

| 字段 | 说明 |
| --- | --- |
| `restStart` | 休息开始，`HH:MM` |
| `restEnd` | 休息结束，`HH:MM`。**比 `restStart` 小就表示跨午夜**（`22:00 → 08:00` 就是当日 22:00 到次日 08:00） |

行为说明：

- 因为时间轴是一整天（00:00–23:59），跨午夜的休息会被拆成两段显示：`00:00–08:00` 和 `22:00–23:59`。
- **安排优先于休息**：如果某天 21:00–23:00 有课，那 `22:00–23:00` 会显示成「忙碌」，休息只剩 `23:00–23:59`。
- **空闲时间已经扣掉休息**：日摘要写「可约 X 小时」，月视图每天的「空闲 X 小时」也都是扣掉休息之后的。
- 完全没安排的一天 = **可约 14小时**（08:00–22:00），不是 24 小时。
- 把两个字段都留空（或设成相同时间）就等于没有休息时段，页面会退回只有「忙碌 / 空闲」两色。

## 3.5 预约信息：`src/data/contact.json`

页面**顶部**「⏰ 最近可约」卡片里的 **📅 预约我的时间** 小按钮（点一下展开，用的是原生 `<details>`，不需要 JS）：

```json
{
  "heading": "预约我的时间",
  "intro": "在时间表里挑一个空闲时段，直接联系我确认即可。价格可以再沟通。",
  "phone": "138-0000-0000",
  "wechat": "your_wechat_id",
  "wechatQr": "",
  "prices": [
    { "label": "白天 08:00–18:00", "price": "¥150 / 小时" },
    { "label": "晚间 18:00–23:00", "price": "¥180 / 小时" },
    { "label": "周末 / 节假日", "price": "¥200 / 小时" }
  ],
  "note": "价格供参考，具体按科目、年级、地点沟通确认。"
}
```

| 字段 | 说明 |
| --- | --- |
| `heading` / `intro` | 标题和一句话说明 |
| `phone` | 电话。会自动生成 `tel:` 链接，手机上点一下就能拨号；旁边有「复制」按钮 |
| `wechat` | 微信号。旁边有「复制」按钮（省得手打错） |
| `wechatQr` | 可选。微信二维码图片路径，例如 `/wechat-qr.png` —— 把图片放进 `public/` 文件夹即可 |
| `prices` | 时段价格表，`label` 是时段、`price` 是价格；写几行就显示几行 |
| `note` | 底部小字备注（例如「价格可商量」） |

- `phone` / `wechat` / `wechatQr` / `prices` / `note` **任何一个留空就不会显示那一行**，不会报错。
- **预约信息对所有访客公开**（这正是它的用途：陌生访客看到空闲时段后联系你）。
- 还在用占位内容时，构建会打印提醒：`⚠️ src/data/contact.json 里还是占位内容…`

## 4. 部署到 GitHub Pages

### 第一次

这个仓库已经配置好了：代码已推送，GitHub Pages 的 **Source 已设为 GitHub Actions**。

### 之后更新网站（平时只需要这三行）

```bash
git add .
git commit -m "update schedule"
git push
```

推送后 GitHub Actions 会自动：`安装依赖 → astro build → 发布到 GitHub Pages`。
大约 1 分钟后刷新 `https://jeremythierrychan.github.io/personal-schedule/` 即可看到更新（也可以在仓库的 **Actions** 标签页看构建进度）。

> 换仓库名 / 换用户名：修改 `.github/workflows/deploy.yml` 里的 `BASE_PATH: /仓库名`，以及 `astro.config.mjs` 里的 `site`。

## 4.9 「最近可约」的规则

顶部那张卡片是**浏览器端**算的，跟着当前时间走（每分钟刷新），跟正在看哪个日期无关：

- 从**此刻北京时间**开始往后找，最多看 **14 天**，列最近 **3** 个时段。
- 只算**够长**的空闲：短于 **60 分钟**的空档不算「可约」（避免把两节课之间的零碎时间当成可约时段）。
- 今天那一条会从「现在」开始算，所以会写成 `今天 12:08–18:00 可约 5小时52分钟`。
- 三个参数（`NEXT_FREE_DAYS` / `NEXT_FREE_COUNT` / `NEXT_FREE_MIN_MINUTES`）在 `src/scripts/app.ts` 顶部，想改随时说。

## 5. ⚠️ 重要限制（请务必读一下）

这是一个**半公开**的静态网站，姓名判断只是前端的显示逻辑，**不是真正的安全认证**：

- 所有日程数据（包括 `title`）都在页面源码里，懂技术的人打开「查看网页源代码」就能看到全部日程。
- 所以**`visitors.json` 里的姓名要当心**：写进去就等于公开一张「输入这个名字能看到全部日程」的通行证。项目初期用过的示例姓名（`Alice`、`小明`）已经删掉，现在只有 `Jeremy`。
- 因此**不要在 `src/data/schedule.json` 里写高度敏感的私人信息**。

如果需要真正的访问控制，就必须要有后端或登录系统，那超出了本项目（纯静态）的范围。

## 6. 项目结构

```
├── .github/workflows/deploy.yml   # GitHub Actions：自动构建并部署到 Pages
├── scripts/import-ics.mjs         # 把 日历/*.ics 转成 src/data/schedule.json
├── 日历/                          # Apple 日历导出的 .ics（已 gitignore，不 push）
├── public/.nojekyll               # 防止 GitHub Pages 的 Jekyll 忽略 _astro 目录
├── src
│   ├── data
│   │   ├── schedule.json          # ← 你平时改这里（忙碌日程，可由 .ics 生成）
│   │   ├── visitors.json          # ← 你平时改这里（授权名单）
│   │   ├── contact.json           # ← 你平时改这里（电话 / 微信 / 时段价格）
│   │   ├── settings.json          # ← 你平时改这里（每天的休息时段）
│   │   └── services.json          # ← 你平时改这里（能教什么）
│   ├── lib
│   │   ├── schedule.ts            # 时间计算：忙碌/空闲时间线、日期工具
│   │   └── access.ts              # 姓名判断：full / guest
│   ├── scripts/app.ts             # 页面交互：输入姓名、切换日期、渲染时间线
│   ├── pages/index.astro          # 首页（唯一的页面）
│   └── styles/global.css          # Tailwind 入口
├── astro.config.mjs
└── package.json
```

## 7. 可以进一步优化的方向（现在都没做）

- 「复制空闲时间」「一键导出 .ics 日历」
- 日视图的方块点一下展开全屏详情
- 日程方块支持点开看详情（现在只有 hover 时的原生 tooltip）
- 让休息时段支持按星期几变化（例如周末晚一点起）
- 让 `schedule.json` 支持颜色分类（学习 / 工作 / 私人各一种颜色）
- 给 `visitors.json` 加过期时间（例如某人的授权只到某个日期）
- 想提高一点门槛：把 `title` 用简单口令加密（AES），只有输入正确姓名时才在浏览器里解密 —— 但**仍然不是真正的安全**，前端密钥终究能被看到
- 支持 `RRULE` 的 `MONTHLY` / `YEARLY`（现在是只保留第一次 + 提醒）
- 支持 iCloud 日历的**订阅地址**，定时自动拉取（现在是手动导出 .ics）
- 预约区块加「复制我看到的空闲时段」按钮，方便对方直接粘贴到微信
- 导入时把同名事件的机构名（全慧文苑 / 沐阳…）拆出来当 `type`，让周视图摘要更有信息量
